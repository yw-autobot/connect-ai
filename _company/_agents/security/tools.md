# 🛡️ Security — 도구 매니페스트

_Security 에이전트가 어떤 도구를 어디까지 자율적으로 쓸 수 있는지 정의합니다._

---

## 자율도 레벨

AUTONOMY_LEVEL: 2

| 값 | 의미 |
|---|---|
| 0 | Off — 도구 전체 비활성 |
| 1 | Read-only — 읽기·분석·보고만, 외부에 쓰기 X |
| 2 | Draft — 초안 작성 후 사용자 승인 게이트 통과해야 실행 ⭐ 기본값 |
| 3 | Auto — 보안 에이전트에는 권장하지 않음 |

---

## 사용 가능한 도구

### `threat_model`
STRIDE/PASTA 기반 위협 모델과 신뢰 경계 정리.

### `secret_scanner`
API 키·토큰·개인정보 노출 후보 탐지. 읽기 전용이어야 합니다.

### `dependency_audit`
npm/pip 의존성 취약점과 공급망 리스크 점검.

### `approval_policy_audit`
삭제·배포·발송·권한 변경 액션의 승인 게이트 누락 점검.

### `gated_fix`
보안 수정 패치를 초안으로 만들고 승인 후 적용합니다. 권한 변경, 삭제, 외부 발송은 항상 별도 승인입니다.

---

## 안전 규칙

- 공격·우회·은닉·파괴 목적의 절차는 실행하지 않습니다.
- 외부 변경, 권한 변경, 배포, 발송, 삭제는 항상 승인 게이트가 필요합니다.
- 모든 발견은 영향도, 근거, 완화책으로 보고합니다.
